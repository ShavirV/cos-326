24) MongoDB

```
{
    $match: { status: "completed" }
},
    {
        $group: {
         _id: "$customerId",
         totalAmount: { $sum: "$amount" },
         totalOrders: { $count: {} }
        }
    },
    {
        $sort: { totalAmount: -1 }
    }
])
```

a) A MongoDB collection is a group of MongoDB documents; functionally similar to a table in a relational database.
It is made up of BSON documents
Has a flexible schema and lives in a DB. Created automatically on first insert or is explicitly instantiated

b) The MongoDB function above is an example of an aggregation pipeline.
A mongoDB pipeline is a linear set of steps, where each step performs some operation to the data,
before passing along the updated data to the next step. They can be utilized to cleanly execute complex operations and aggregations on data.

This particular pipeline first matches orders that have the status "Completed". These completed orders are grouped by customer ID. For each group, it calculated the total amount each customer has spent, as well as the total number of orders that they have completed.
Finally these groupings are sorted by total amount, descending.

26) parallel relational DBs vs MapReduce/Hadoop systems

- Both split data across many nodes and process it in parallel, allowing handling of big data
- A relational DBMS needs structured dat loaded into tables under a fixed schema. Hadoop stores raw files in its own HDFS and applied the structure when reading.
- RDBMS uses declarative SQL, an optimizer decides how to run it. MapReduce needs you to write procedural map and reduce function which is why tools like Hive and Pig were created (for ease)
- Both are fault tolerant and are designed with scalability in mind
- Relational supports ACID, indexes and optimisation. Hadoop uses brute force scans and gives no transactions.

b) Describing knowledge discovered during data mining

- Can use **Association** rules "if X then Y".
- **Classification** rules or a decision tree assigning records to classes. like classifying applicants for credit as low, medium, and high risk
- **Clustering** Grouping similar records without predefined classes, such as customer segments.
- Sequential patterns and patterns in time series

27) A fact table in a data warehouse:

Data warehouse: A large store of organised data, according to business needs, from separate operational systems. It's usually non volatile and time variant (time needs to be stored with data)

Fact table: the central table of the star schema. It holds the measures (numeric values) and foreign keys to every dimension table. All of these foreign keys together form its primary key.

Example - A 'Sales' fact table with Dimension tables **time, branch, product and promotion**

Its role in OLAP: Operations such as roll-up, drill-down, slice, dice and pivot work by aggregating the fact table's measures along the dimensions. the fact table supplies the cell values of the data cube.
